# 独立实现来源审计

审计日期：2026-07-31

## 历史来源说明

本文所称的早期参考实现是 Rayvich 开发的 RZMenu。RZMenu 及其对《绝区零》交互式模型变形技术的早期探索，是 JiggleForge 最初的技术参考和研究起点。

本审计用于确认当前 JiggleForge 实现没有复制或继续沿用参考实现特有的代码、命名、数据布局和控制流。实现独立性与历史来源是两个不同的问题：前者说明当前代码如何形成，后者记录促使研究开始的先行工作。本审计不否认或取代对 Rayvich / RZMenu 的致谢；完整记录见 [ACKNOWLEDGEMENTS.md](../../ACKNOWLEDGEMENTS.md)。

对照对象：

- 开发初期用于技术研究的 Rayvich / RZMenu 参考 Mod 归档
- 当前 JiggleForge 工作树

本报告是工程来源审计，用于确认实现边界，不构成法律意见。

## 方法

1. 解压参考 Mod，枚举全部 INI、HLSL、说明和脚本。
2. 枚举当前仓库中受版本控制的源码与文本文件。
3. 比较标准化换行后的完整文件 SHA-256。
4. 对当前每个唯一 HLSL 与参考 Mod 的全部 HLSL 比较：
   - 原始非空行重合；
   - 去除标识符差异后的结构化行重合；
   - 最长连续公共片段；
   - 函数名、常量布局、资源槽位和控制流人工复核。
5. 搜索可能从参考实现复制而来的文件头、角色名、旧命名、函数和状态标识。
6. 对高相似结果区分“游戏原始 VS 指令”“通用 HLSL 样板”和“Mod 自有实现”。

## 结果

- 参考源码/文本文件：45 个，其中 HLSL 44 个。
- 当前审计源码/文本文件：86 个。
- 完整文件 SHA-256 相同：0 个。
- 当前唯一 HLSL：17 个；每个都与参考 HLSL 全量交叉比较。
- 未发现参考 Mod 的变形、拾取、状态更新、重置、交互或参数登记实现残留。
- 未发现从参考实现复制而来的文件头、角色名、旧函数前缀或其特有状态布局。

## 保留内容的来源分类

- 游戏 VS replacement 中的大段反编译指令来自游戏自身导出，不来自参考 Mod 的变形实现。
- `GetDimensions`、线程边界判断、`float4` 缓冲访问、重心插值和向量归一化属于 D3D/HLSL 常规做法。
- 世界空间拾取、输入控制、运动求解、依赖状态消费、Kelvinlet 风格体积响应、Jacobian 法线变换和应用生成器均由 JiggleForge 独立实现并由本仓库测试约束。

## 结论

在本次逐文件、逐 HLSL 和人工结构审查范围内，没有发现 RZMenu 参考实现的同源代码遗留。正式运行时代码可以按 JiggleForge 自有结构发布；这一工程结论不改变 Rayvich / RZMenu 作为最初技术参考和研究起点的历史贡献。
